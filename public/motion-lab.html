문제점What's actually wrong

  • tap 피드백 부재 — 모바일 우선 서비스인데 버튼/카드에 press 시 눌리는 느낌(scale/opacity)이 전혀 없다. hover 의존 UI가 모바일에서는 그대로 "무반응"으로 느껴진다.
  • duration 일관성 자체가 없음 — 전환이 존재하는 지점(150ms)과 존재하지 않는 지점(0ms)만 있고, 그 사이 단계(200~300ms급 normal/slow)가 설계된 적이 없다.
  • 모달/바텀시트 enter·exit 없음 — 화면이 즉시 나타나고 사라져 위치 전환의 공간감이 없다. 특히 지도 위에 뜨는 오버레이일수록 급작스럽게 느껴진다.
  • 로딩 신호가 pulse 하나뿐 — 지도 위치추적 외 다른 비동기 동작(글쓰기 제출, 프로필 저장, 매칭 요청)에는 로딩 상태 모션이 확인되지 않아 사용자가 "눌렸는지" 확신하기 어렵다.
  • 과도한 motion은 없음(역설적 문제) — AI 생성 UI 특유의 bounce/scale/그라디언트 애니메이션은 전혀 없다. 다만 그 결과가 "신뢰감 있는 정적임"이 아니라 "반응이 없어 보임"으로 읽힌다.
  • 지도 사용성을 방해하는 애니메이션은 없음 — 긍정적 발견. 다만 이는 의도적 설계가 아니라 모션 자체가 없기 때문.

삭제 권장 / 유지 권장 animation

DROP
  • 없음 — 삭제할 정도로 과한 애니메이션이 현재 존재하지 않는다.
  • 단, animate-pulse의 2000ms 주기는 v1.2에서 더 빠른 인지 신호(예: 1200~1400ms)로 조정 권장.
KEEP
  • transition-shadow (150ms) — 카테고리 타일의 미묘한 hover 피드백. 방향은 맞음, 대상 범위만 버튼/카드 전체로 확장.
  • pulse 로딩 신호 — 위치추적처럼 "기다림"이 있는 지점의 개념 자체는 유지, duration/easing만 토큰화.

CSS 변수 예시

/* globals.css 또는 :root */
:root {
  --motion-fast: 120ms;
  --motion-md: 200ms;
  --motion-slow: 280ms;

  --easing-standard: cubic-bezier(0.2, 0, 0, 1);
  --easing-emphasized: cubic-bezier(0.2, 0, 0, 1);
}

/* 버튼 / 카드 공통 tap feedback */
.tappable {
  transition: transform var(--motion-fast) var(--easing-standard),
              opacity var(--motion-fast) var(--easing-standard);
}
.tappable:active {
  transform: scale(0.98);
  opacity: 0.92;
}

/* 바텀시트 enter/exit */
.sheet-enter {
  transform: translateY(12px);
  opacity: 0;
}
.sheet-enter-active {
  transform: translateY(0);
  opacity: 1;
  transition: transform var(--motion-slow) var(--easing-emphasized),
              opacity var(--motion-slow) var(--easing-emphasized);
}

/* 접근성: reduced motion 대응 */
@media (prefers-reduced-motion: reduce) {
  * {
    transition-duration: 0.001ms !important;
    animation-duration: 0.001ms !important;
  }
}

라이브 스타일시트 검사 결과 prefers-reduced-motion 미디어쿼리가 존재하지 않음. 현재는 모션이 거의 없어 실질적 위험은 낮지만, v1.2에서 tap/enter-exit 모션을 추가하는 순간 반드시 위 CSS 변수 예시의 fallback 블록을 함께 넣어야 한다.

Figma motion guideline

  • Prototype 설정 — Smart Animate, Easing: Custom cubic-bezier(0.2, 0, 0, 1), Duration: Fast=120ms / Medium=200ms / Slow=280ms 세 프리셋만 사용.
  • 컴포넌트 variant — 모든 버튼/카드 컴포넌트에 Default / Pressed variant 추가(Hover variant는 참고용, 실제 모바일 적용은 Pressed 기준).
  • 바텀시트/모달 프레임 — "Move in" (Y +12px → 0, opacity 0 → 100%), Slow 토큰 적용.
  • 주석 규칙 — 각 인터랙션 프레임에 motion: fast|md|slow 태그를 텍스트 레이어로 명시해 개발 핸드오프 시 토큰 매핑 오차를 없앤다.

v0 구현 시 적용할 motion rule

  • Tailwind 커스텀 유틸리티로 duration-fast(120ms) / duration-md(200ms) / duration-slow(280ms) 및 ease-standard 토큰을 tailwind.config.js에 추가하고, 임의의 duration-[Nms] 하드코딩은 지양한다.
  • 모든 clickable 요소(버튼/카드/필터 chip)에 active:scale-[0.98] transition-transform duration-fast 패턴을 기본값으로 적용해 tap 피드백을 통일한다.
  • 모달/바텀시트는 컨테이너 등장에만 duration-slow ease-standard로 opacity+translateY 조합을 쓰고, 배경 딤(dim)은 별도로 duration-md 사용.
  • 지도 위 오버레이(마커 팝업 등)는 motion 자체보다 등장 지점의 명확성이 더 중요하므로 애니메이션을 추가하지 않거나 duration-fast만 적용한다.
  • 새 로딩 상태를 추가할 때는 animate-pulse를 그대로 재사용하되, Tailwind 기본 2000ms 대신 커스텀 animate-pulse-fast(1300ms) 유틸을 우선 검토한다.
  • Supabase/API/라우팅/hooks/지도 로직은 이번 리포트의 스코프가 아니므로, 위 rule은 어디까지나 클래스명·CSS 토큰 레벨에서만 적용한다.
